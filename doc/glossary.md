# Project Glossary

This glossary describes the MVP vocabulary. The domain model is a design; the current implementation provides the web connectivity foundation. See [domain design](./domain-design.md) and [web architecture](./web-architecture.md) for details.

| Term | Meaning |
|---|---|
| **Test suite** (`TestSuite`) | A named collection of one or more test cases. |
| **Test case** (`TestCase`) | A test definition containing a prompt, optional variables and evaluation criteria, and one or more expectations. |
| **Prompt** | The instruction sent to the model under test. It may contain placeholders filled using variables. |
| **Variables** | Named values supplied for placeholders in a test prompt. |
| **Golden reference** | A reference answer used by evaluators for comparison with the model output. |
| **Rubric** | Criteria used to judge an output, for example by an LLM judge. |
| **Expectation** | A configured check with an ID, name, evaluator type, threshold and options. Multiple expectations can use the same evaluator. |
| **Evaluator** | An algorithm that evaluates an output against an expectation and returns a score. The MVP describes exact match, semantic similarity and LLM judge strategies. |
| **Threshold** | The minimum score required for an expectation to pass, expressed on that evaluator's scale. |
| **Score** (`EvalScore`) | A recorded evaluation outcome, including its value, scale and feedback. An expectation outcome also identifies the check, its threshold and pass/fail status; an evaluator error is recorded as a failure. |
| **Test result** (`EvalResult`) | The recorded outcome of one test in a run: output or execution error, scores and test pass/fail status. A test passes when execution succeeds and all its expectations pass. |
| **Run** (`EvalRun`) | One execution of a suite, recording its results, start time and provider/model. |
| **Runner** (`EvalRunner`) | The coordinator that executes each test through the provider, applies its expectations and records the results in a run. |
| **Report** (`EvalReport`) | A view of a completed run and its overall judgment, generated by `ReportGenerator`. It exposes individual results and failed expectations. |
| **Overall score evaluator** (`OverallScoreEvaluator`) | The strategy that calculates the overall judgment for a run. Its formula is part of the exercise; scores on different scales cannot simply be averaged. |
| **Model provider** (`ModelProvider`) | The contract used by the runner to request a model response from a prompt and variables. A provider adapter translates this contract to an external API. |
| **System under test (SUT)** | The selected provider and model whose responses are being tested. |
| **Export** | A JSON representation of a suite, its tests and their related run and result history. Export can occur before the first run and does not require a new run or report. |
| **Health check** | The current `GET /health` operation, which checks server connectivity rather than domain or dependency readiness. |

Historical results retain test IDs and recorded outcomes, but the MVP does not store test versions or prompt snapshots.
